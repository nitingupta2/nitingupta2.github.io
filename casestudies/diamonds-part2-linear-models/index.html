Diamonds - Part 2 - A cut above - Building Linear Models

Dec 21, 2016 case studies

Other posts in this series:

  • Diamonds - Part 1 - In the rough - An Exploratory Data Analysis
  • Diamonds - Part 3 - A polished gem - Building Non-linear Models

In a previous post in this series, we explored the diamonds dataset. We found that price has a strong correlation with carat, x, y and z, and that log(price) has an almost straight-line relationship with log(carat). For diamonds of similar weight, clarity and color also seemed to help predict the price.

In this post, we build linear models and find out how well they predict the price of diamonds. A linear model predicts a value by adding up the features, each multiplied by a number (a coefficient) that the model learns from the data.

First, let’s build a simple base model that uses all the features, without any changes to them. Its results give us a starting point to compare with:

The model summary shows that this model is overfitted. An overfitted model learns the noise in the data, not only the true patterns, so it does not work well on new data. For example, we know that depth and table have no effect on price, but the model says that they are very important.

The table above also shows the root mean squared error (RMSE) and other metrics. RMSE is the typical size of a prediction error, in the same units as the price. A lower RMSE means better predictions.

Let’s plot the predicted prices against the actual prices, to see how well this base model works.

augment(model_lm, diamonds) %>%
  eda_plot_predicted_vs_actual("price", ".fitted", nLabel = 0, labelsScale = scales::label_dollar(accuracy = 1)) +
  labs(title = "Predicted v/s actual price from a base linear model")

If the predictions are good, the points are close to the red line at 45 degrees, where the predicted price is equal to the actual price. A point above the line is a diamond whose predicted price is too high, and a point below the line is a diamond whose predicted price is too low. This base model predicts the prices badly. Worst of all, it predicts negative prices for cheap diamonds. To prevent such impossible results, we must use log(price) instead of price.

Feature Engineering

Feature engineering means that we create new features from the existing features, to make the patterns easier for a model to learn.

We know that the price of a diamond has a strong correlation with its size. If all other things are equal, a larger diamond has a higher price.

As a first estimate, we can treat a diamond as a box with the dimensions x, y and z. Then its volume is x * y * z. These 3 dimensions have a strong correlation with each other. So we can calculate one average dimension as the cube root of volume. This average dimension keeps a straight-line relationship with log(price).

We can also calculate an average dimension with high school chemistry. Mass, volume and density are related by this equation:

\[density = \frac{mass}{volume}\]

1 carat is 0.2 grams. If we divide the mass by the density of diamond (3.51 grams per cubic centimeter), we get the volume. The cube root of the volume gives an average dimension.

dfInput <- diamonds %>%
  mutate(row = row_number(),
         volume = x*y*z,
         `average dimension` = volume ^ (1/3),
         volume2 = carat * 0.2/3.51,
         `average dimension2` = (volume2 ^ (1/3)) * 10)   # Multiply by 10 to convert from cm to mm

eda_plot_scatter(dfInput, c("average dimension", "average dimension2"), "price", yLabelsScale = scales::dollar,
                 nLabel = 3, feature_id = "row", labelBy = "leverage") +
  labs(title = "Scatterplot of price v/s average dimension")

# the point with the most leverage on the linear fit of price on the dimension-based feature
dfLeverage <- dfInput %>%
  mutate(leverage = hatvalues(lm(price ~ `average dimension`, data = dfInput))) %>%
  slice_max(leverage, n = 1)

The two methods give similar results, but the density method gives a narrower range. Which method is more reliable? In each panel, the labels show the row numbers of the diamonds with the most leverage. Leverage tells how much a point can pull the straight line towards itself. Points that are far from the others along the x axis have the most leverage. With the dimensions, the most extreme point is the diamond in row 24068. It is a 2 carat diamond with a recorded width y of 58.9 mm. This value is clearly a recording error. The other labelled points are diamonds with an average dimension of 0. With the density method, the labelled points are simply the largest diamonds in the dataset. Also, 20 values of z are 0. In 7 of these diamonds, x and y are also 0. So these dimensions were not recorded correctly.

For all of these diamonds, the carat values are correct. So carat is probably more accurate than the dimensions, and we prefer the density method to create this feature.

Also, the density is a constant. So we do not need to divide by it to calculate the volume. Instead, we can take the cube root of carat itself. Then we expect a straight-line relationship between \(log(price)\) and \(carat^{1/3}\). A straight-line relationship is what a linear model needs, because the model adds up its features in a straight-line way.

The geometry suggests a cube root. But does the cube root give the best straight line? Let’s compare it with other transforms. Each panel shows the R-squared of a straight line through the points of log(price):

p_transforms <- eda_plot_transforms(diamonds, "carat", "price")
p_transforms

# R-squared of each transform, in the order of the panels
vR2_carat <- p_transforms$data %>%
  distinct(transform, r_squared) %>%
  pull(r_squared) %>%
  set_names(c("identity", "log", "sqrt", "cuberoot"))

The cube root (R-squared 0.924) is much better than carat without a transform (0.847). But log(carat) is even better (0.933). A straight-line relationship between \(log(price)\) and \(log(carat)\) is easy to understand: the coefficient of \(log(carat)\) is the percentage change in price when carat increases by 1%. We will try both transforms in our models.

Training Linear Models

These are the steps to build the linear models and measure how well they work:

  • Split the dataset into two sets: a training set with 75% of the diamonds and a testing set with 25%. The model learns from the training set. Then we check its predictions on the testing set, which has diamonds that the model has not seen.
  • clarity is one of the most important features. So we split the data in a way that keeps the same mix of clarity grades in both sets. This is called stratified sampling.
  • Train (fit) a linear model on the training set.
  • Make predictions on the testing set and calculate the metrics.
  • Put all the steps above in a function that takes the model formula and a random seed. The seed controls which diamonds go into each set. With different seeds, we get different random splits, so one lucky or unlucky split does not decide the results.
  • Run each model several times with different seeds, and calculate its average metrics. These averages show how well the model works on new data.

Here is one split into a training set and a testing set, stratified by clarity. Both sets have a similar mix of clarity grades.

We ran each model 5 times with different seeds. Here are the average metrics. R-squared (rsq) tells how much of the variation in price the model explains, and the mean absolute error (mae) is the average size of a prediction error:

fit_linear_model <- function(randomSeed, model_formula, get_model = FALSE) {

  set.seed(randomSeed)
  train_split <- diamonds %>% 
    select(price, everything()) %>% 
    initial_split(prop = 0.75, strata = "clarity")
  
  dfTrain <- training(train_split)
  dfTest <- testing(train_split)

  # fit a linear model
  model_lm <- lm(model_formula, data = dfTrain)
  
  # predict on testing set to determine rmse  
  predict_lm <- predict(model_lm, dfTest)

  # predict on testing set with outliers
  dfResults <- dfTest %>% 
    mutate(actual = price) %>% 
    mutate(estimate = predict_lm %>% exp()) %>% 
    select(actual, estimate)
  
  if(get_model) {
    return(list(model_lm, dfResults))
  } else {
    return(dfResults)
  }
}
set.seed(1000)
vRandomSeeds <- sample(9999, 5)
dfModels <- expand_grid(seed = vRandomSeeds, 
                        model = c("log(price) ~ .",
                                  "log(price) ~ I(carat^(1/3))",
                                  "log(price) ~ I(carat^(1/3)) + clarity",
                                  "log(price) ~ I(carat^(1/3)) + clarity + color",
                                  "log(price) ~ I(carat^(1/3)) + clarity + color + cut",
                                  "log(price) ~ log(carat)",
                                  "log(price) ~ log(carat) + clarity",
                                  "log(price) ~ log(carat) + clarity + color",
                                  "log(price) ~ log(carat) + clarity + color + cut")) %>%

  mutate(metrics = map(results, ~ metrics(.x, truth = actual, estimate = estimate))) %>%

The first model, with all the features, is overfitted.

Each model with log(carat) is much better than the same model with the cube root of carat. With clarity and color, the RMSE goes down from $1,725 to $816, and the R-squared goes up from 0.888 to 0.959.

The model with log(carat), clarity and color gives the best combination of a low RMSE and a high R-squared, so it explains the most variation. This is our final model. If we add cut, the RMSE goes down only a little, to $795. So we do not use cut, and we keep the model simpler.

A residual is the difference between the actual value and the predicted value, here of log(price). Residual plots show if the errors of a model have a pattern. If the model is good, the residuals look like random noise around 0. Here are the four standard residual plots of our final model:

# labels are off: the row numbers of a random training set do not identify the diamonds
eda_plot_residuals(fit_lm[[1]], nLabel = 0)

vStdResid <- rstandard(fit_lm[[1]])
vCooks <- cooks.distance(fit_lm[[1]])
  • Residuals vs Fitted: The residuals stay close to 0 for all predicted values, and the red smooth line is almost flat. So the model captures the relationship well. The small curve shows that a little non-linearity remains. At the highest predicted values, the residuals form a sloping edge below 0. The reason is that no diamond in the data costs more than $18,823, so for the largest predictions, the actual price can only be lower.
  • Normal Q-Q: In the middle, the points follow the dashed line, so most residuals are normally distributed. But the tails, especially the upper tail, are longer: some diamonds cost much more than the model predicts. 160 of the 40453 diamonds in the training set have a standardized residual larger than 3, or smaller than -3.
  • Scale-Location: The smooth line is almost flat, so the spread of the errors is about the same for cheap and expensive diamonds. The log of price makes the spread stable. Without it, the errors grow with the price.
  • Residuals vs Leverage: No diamond has a high leverage. The largest Cook’s distance is only 0.0067. A point needs a Cook’s distance of about 0.5 or more to pull the model strongly, so the plot does not even reach the dashed contours that mark 0.5 and 1. No single diamond controls the model.

If clarity and color do not change, a 1% increase in carat increases the predicted price by about 1.88%.

The points are close to the 45-degree line. But at the high end, the differences between the actual and predicted prices become larger. The predictions of the final model are also much less extreme. The most expensive diamond in the testing set costs $18,804. The highest predicted price is $28,130. But the cube root model predicts prices as high as $59,082 for the same testing set. Like all linear models, the final model can still predict prices above the highest prices in the data (this is called extrapolation).
