Diamonds - Part 2 - A cut above - Building Linear Models

Dec 21, 2016 case studies

In a previous post in this series, we did an exploratory data analysis of the diamonds dataset and found that carat, x, y, z were strongly correlated with price, and that log(price) was close to linear in log(carat). For diamonds of similar weight, clarity and color also appeared to provide some predictive ability.

In this post, we will build linear models and see how well they predict the price of diamonds.

Before we do any transformations, feature engineering or feature selections for our model, let’s see what kind of results we get from a base linear model, that uses all the features to predict price:

Feature Engineering

We know the price of a diamond is strongly correlated with its size. All things equal, the larger the diamond, the greater its price.

As a first approximation, we can assume a diamond is a cuboid with dimensions x, y and z. Then, we can compute its volume as x * y * z. As these 3 dimensions are highly correlated, we can compute a geometrical average dimension by taking the cube root of volume, and retain a linear relationship with log(price).

Another way to calculate an average dimension is by using high school chemistry. Mass, volume and density are related to each other by the equation:

$ density = mass/volume $

We can find out that 1 carat = 0.2 gms. Dividing by the density of diamond (3.51 gms/cc) would give us its volume in cc, which could be converted to a geometrical average dimension by taking the cube root.

dfInput <- diamonds %>%
  mutate(row = row_number(),
         volume = x*y*z,
         `average dimension` = volume ^ (1/3),
         volume2 = carat * 0.2/3.51,
         `average dimension2` = (volume2 ^ (1/3)) * 10)   # Multiply by 10 to convert from cm to mm

eda_plot_scatter(dfInput, c("average dimension", "average dimension2"), "price", yLabelsScale = scales::dollar,
                 nLabel = 3, feature_id = "row", labelBy = "leverage") +
  labs(title = "Scatterplot of price v/s average dimension")

# the point with the most leverage on the linear fit of price on the dimension-based feature
dfLeverage <- dfInput %>%
  mutate(leverage = hatvalues(lm(price ~ `average dimension`, data = dfInput))) %>%
  slice_max(leverage, n = 1)

Even though both methods yield similar results, we could see that the density method results in a narrower range. But which method would be more robust? Each panel labels, by row number, the diamonds with the most leverage on a linear fit, i.e. the points that are furthest from the rest along the x axis. With the dimensions, the most extreme point is the diamond in row 24068: a 2 carat diamond with a recorded width y of 58.9 mm, which is clearly a recording error. The other labelled points are diamonds with an average dimension of 0. With the density method, the labelled points are simply the largest diamonds in the dataset. In all of these records, the carat values were recorded reliably and are probably more accurate than the dimensions. Hence, we might prefer the density method of generating this feature.

Furthermore, since density is a constant, dividing by a constant to calculate volume isn’t really necessary. Instead, a cube root transformation could be applied to carat itself for the purposes of predictive modelling that would result in a linear relationship between \(log(price)\) and \(carat^{1/3}\). It is the reason why we’re fitting a linear model because the model is linear in its parameters.

The geometric argument favours a cube root, but is it the transform that makes the relationship most linear? Let’s compare it with others, labelling each panel with the R-squared of a linear fit of log(price):

p_transforms <- eda_plot_transforms(diamonds, "carat", "price")
p_transforms

# R-squared of each transform, in the order of the panels
vR2_carat <- p_transforms$data %>%
  distinct(transform, r_squared) %>%
  pull(r_squared) %>%
  set_names(c("identity", "log", "sqrt", "cuberoot"))

The cube root (R-squared 0.924) is a big improvement on untransformed carat (0.847), but log(carat) does even better (0.933). A linear relationship between \(log(price)\) and \(log(carat)\) has a simple interpretation: the coefficient of \(log(carat)\) is the percentage change in price for a 1% change in carat. We will try both transforms in our models.

Training Linear Models

Here are the steps for building linear models and computing metrics:

  • Partition the dataset into training and testing sets in the proportion 75% and 25% respectively.
  • Since clarity is one of the main predictors, stratify the partitioning by clarity, so both training and testing sets have the same distributions of this feature.
  • Fit a linear model with the training set.
  • Make predictions on the testing set and determine model metrics.
  • Wrap all the steps above inside a function in which the model formula and a seed could be passed. Since the seed determines the random partitioning, it helps to minimize vagaries in partitioning the training and testing sets before fitting models.
  • Run multiple iterations of a model with different seeds, and compute its average metrics, that would reflect the results on unseen data.

Here’s a sample split of training and testing set, stratified by clarity. As we can see, the training and testing sets have similar distributions.

fit_linear_model <- function(randomSeed, model_formula, get_model = FALSE) {

  set.seed(randomSeed)
  train_split <- diamonds %>% 
    select(price, everything()) %>% 
    initial_split(prop = 0.75, strata = "clarity")
  
  dfTrain <- training(train_split)
  dfTest <- testing(train_split)

  # fit a linear model
  model_lm <- lm(model_formula, data = dfTrain)
  
  # predict on testing set to determine rmse  
  predict_lm <- predict(model_lm, dfTest)

  # predict on testing set with outliers
  dfResults <- dfTest %>% 
    mutate(actual = price) %>% 
    mutate(estimate = predict_lm %>% exp()) %>% 
    select(actual, estimate)
  
  if(get_model) {
    return(list(model_lm, dfResults))
  } else {
    return(dfResults)
  }
}
set.seed(1000)
vRandomSeeds <- sample(9999, 5)
dfModels <- expand_grid(seed = vRandomSeeds, 
                        model = c("log(price) ~ .",
                                  "log(price) ~ I(carat^(1/3))",
                                  "log(price) ~ I(carat^(1/3)) + clarity",
                                  "log(price) ~ I(carat^(1/3)) + clarity + color",
                                  "log(price) ~ I(carat^(1/3)) + clarity + color + cut",
                                  "log(price) ~ log(carat)",
                                  "log(price) ~ log(carat) + clarity",
                                  "log(price) ~ log(carat) + clarity + color",
                                  "log(price) ~ log(carat) + clarity + color + cut")) %>%
  mutate(results = map2(seed, model, ~ fit_linear_model(.x, as.formula(.y)))) %>% 
  mutate(metrics = map(results, ~ metrics(.x, truth = actual, estimate = estimate))) %>%
  select(-results) %>% 
  unnest(cols = metrics) %>% 
  select(-.estimator) %>% 
  spread(.metric, .estimate) %>% 
  group_by(model) %>% 
  summarise_at(vars(rmse, rsq, mae), mean)

The first model with all predictors is an overfitted one.

Every model with log(carat) does much better than its counterpart with the cube root of carat. With clarity and color, the root mean squared error falls from $1,725 to $816, and r-squared rises from 0.888 to 0.959.

The model with log(carat), clarity and color provides the best combination of root mean squared error and r-squared, that explains the most variance. This is our final model. Including cut in the model has diminishing benefits: it lowers the root mean squared error only to $795, so we leave it out for a simpler model.

The points lie close to the 45 degrees line, although the variance between actual and predicted prices increases at the high end. The final model’s predictions are also far less extreme. The most expensive diamond in the testing set costs $18,804. The highest predicted price is $28,130, whereas the cube root model predicts prices as high as $59,082 on the same testing set. Like any linear model, it can still extrapolate beyond the prices in the data at the high end.
